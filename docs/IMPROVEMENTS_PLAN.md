## №3. Ресайз рамки за грань (баг) — СДЕЛАНО

> Выполнено. Регрессия `resizingBorderKeepsWorkingOnRepeatedDrags` падала без фикса
> (второй ресайз не менял ширину) и зелёная с ним; юнит-тесты `NearEdgeTest` (6 шт.).
> Полный suite: 48 классов, 338 тестов, 0 падений.

**Симптом.** После одного успешного перетаскивания грани последующие попытки изменить
размер рамки (десятки движений и кликов) часто не срабатывают.

**Причина.** `nearEdge` (`feature/builder/EditorGestures.kt`) смешивает координатные
пространства: прямоугольник рамки берётся в канвасных единицах и сдвигается только на
`transform.origin` — без умножения на `transform.scale`, — а сравнивается с экранной
точкой нажатия и экранным допуском (`handlePx`, 24dp). На экране грань отрисована в
`origin + c * scale`; при fit-масштабе ≈ 0.3 промах для канвасной координаты 800 —
почти 300 px. Проба совпадает только для граней с канвасной координатой ≈ 0 (или при
`scale ≈ 1`). Первая рамка пустого комбо полнохолстовая, её левая/верхняя грань лежат
на 0 — они хватаются; после центр-анкерного ресайза грань уезжает от 0, и проба
перестаёт её находить: жест вырождается в сдвиг фото/рамки/вида. Усугубляют двойные
клики при повторных попытках (молча переключают EDIT↔BORDER) и клик мимо рамки
(сбрасывает выделение — ручки исчезают).

**Фикс.**
- Проба грани — в одном (канвасном) пространстве: `nearEdge(toCanvas(down.position),
  border.rect(), tolerance = handlePx / scale)`; `handlePx` передаётся `State`-обёрткой
  (правило AGENTS: всё композиционно-зависимое читается через `State`).
- Сама проба вынесена в чистую top-level-функцию `nearEdge(p, border, tolerance)`, её
  вызывает локальная `edgeHitAt` (выбор рамки + перевод единиц).

**Тесты.**
- Регрессия в `ComboBuilderGesturesTest`: ресайз левой грани (работает и до фикса —
  канвасная координата 0), затем повторный ресайз правой грани на её новом месте
  (до фикса проба мимо — ширина не меняется).
- Юнит-тест пробы грани (`NearEdgeTest`): грани, допуск в канвасных единицах (широкая
  полоса при zoom < 1), углы (приоритет горизонтальной оси), точки за допуском.

**Отложено до ручной проверки.** Страховка от потерянного release вне окна
(`awaitEachGesture` живёт до release) и CANCEL-путь ресайза (сейчас END-time
`refreshBitmaps()` теряется при обрыве) — делаем, если владелец подтвердит залипание.

## №2. Обрезка по границам холста (изменение поведения) — СДЕЛАНО

> Выполнено. Пиксельный тест `DrawComboClipTest` падал без фикса (рамка красила пиксель за
> краем холста) и зелёный с ним. Обновлены README (описание `drawCombo`/оверлея) и
> USER_GUIDE (подробности режимов рамки).

**Симптом.** Всё, что выходит за границы холста, видно: в редакторе — на сером фоне, в
превью списка — на карточке, в плеере — на чёрных полях.

**Причина.** Обрезки по прямоугольнику холста нет нигде; центр рамки зажат на холсте
(`ItemGestures`), а её корпус может выходить за край.

**Фикс.** Один `clipRect(0, 0, canvasW, canvasH)` внутри `translate/scale` в
`drawCombo()` (`core/render/DrawCombo.kt`): холст целиком рисуется только здесь, поэтому
исправление сразу действует в редакторе, превью списка и плеере (WYSIWYG сохраняется).
Оверлей выделения редактора обрезается по экранному прямоугольнику холста — ничего не
свисает; хит-зоны граней остаются (24dp полоса вдоль грани).

**Тест.** Пиксельный тест `drawCombo` (`DrawComboClipTest`): рамка, выходящая за край,
не оставляет пикселей вне прямоугольника холста; внутри холста рисуется; фон за края
не заливается.

## №1. Добавление следующей рамки (новая функциональность) — СДЕЛАНО, затем пересмотрено

> Пересмотрено упрощением «одна рамка — одно фото» (`docs/PHASE5_SIMPLIFY_CHANGELOG.md`): рамок без
> фото больше нет, `+Frame` открывает выбор фото и создаёт по рамке на каждое выбранное (`AddItems`).
> Текст ниже описывает прежнее решение и сохранён для истории.

> Выполнено. `TOOL_TAG_ADD_ITEM` = `builder_tool_add_item`, подпись «+Frame».
> Тесты: `DraftEditorTest` (2), `ComboBuilderViewModelTest` (2), `ComboBuilderToolbarTest` (1).
> Полный suite: 49 классов, 344 теста, 0 падений; дымовой запуск без исключений.
> Обновлены README и USER_GUIDE.

**Симптом.** В ручном создании комбо нет способа добавить следующую рамку после работы
с первой.

**Состояние.** Рамки рождаются только при создании комбо (по одной на выбранное фото
или одна пустая для «New combo»). В билдере нет ни события, ни операции `DraftEditor`,
ни кнопки.

**Решение владельца (принято по рекомендации).** Новая рамка создаётся по центру
холста, размер 50%×50% (800×450 канвасных единиц), `FramingMode.FREE`, сразу выделена;
пустая рамка без фото при сохранении отбрасывается — как и любая пустая. Кнопка
доступна в любом редактируемом комбо.

**Состав.**
- `DraftEditor.addItem(...)` — чистая операция над драфтами: лимит `Const.MAX_ITEMS = 10`,
  новая рамка на верхнем слое (zIndex), выделение переводят вызывающие;
- `BuilderEvent.AddItem` + обработка в `ComboBuilderViewModel` одним undo-шагом;
- кнопка `+Frame` в `BuilderToolbar` рядом с `+Photo` (tag `TOOL_TAG_ADD_ITEM`),
  активна при `items.size < MAX_ITEMS`.

**Тесты.** `DraftEditorTest` (геометрия, лимит, порядок слоёв), `ComboBuilderViewModelTest`
(выделение, `isDirty`, один undo-шаг), `ComboBuilderToolbarTest` (вкл/выкл на лимите).
